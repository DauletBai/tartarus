Для общего решателя рассматриваю HiGHS368, поддерживающий линейные, смешанные целочисленные и квадратичные задачи. Он написан на C++ и распространяется по лицензии MIT. Возможное применение — отдельный ограниченный процесс: Rust передаёт задачу и независимо проверяет полученные количества. Это вариант архитектуры, а не сообщение об уже встроенном решателе. Перенос прикладных механизмов из прежних проектов выполняется на Rust; вспомогательные исследовательские скрипты Python не получают права изменять денежный реестр.

Планирование я разделяю по территориям, периодам и группам ресурсов, сохраняя согласование общих запасов. Для миллиарда людей не требуется каждую секунду решать одну плотную систему из миллиарда неизвестных. Однако разбиение само по себе не гарантирует общего оптимума. В прототипе ещё нужно ограничить рассылку событий только затронутыми расчётами, измерить нагрузку на базу и проверить межрегиональные связи.
